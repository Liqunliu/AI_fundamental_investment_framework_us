# Standalone Valuation Module

## Overview

The `/valuation` skill runs a multi-method valuation analysis on a US stock. It uses
`data_pack.md` as the primary data source and optionally applies qualitative adjustments
from `qualitative_report.md` (generated by `/business-analysis`).

Unlike strategy-specific analysis (QY, Cigar, Cyclical), this module focuses purely on
estimating intrinsic value — no portfolio management, no factor gates.

## Usage

```
/valuation AAPL
/valuation NVO --source bloomberg
```

## Prerequisites

| File | Required? | How to Generate |
|------|-----------|-----------------|
| `output/{TICKER}/data_pack.md` | YES (auto-collected if missing) | `python3 scripts/yfinance_collector.py --ticker {TICKER}` |
| `output/{TICKER}/qualitative_report.md` | Optional (enables qualitative adjustments) | `/business-analysis {TICKER}` |
| `output/{TICKER}/{TICKER}_factor_inputs.md` | Optional (pre-computed metrics) | `python3 scripts/calculate_factor_inputs.py` |

## Pipeline

```
Step 1: Data Collection (skip if files exist and < 7 days old)
  yfinance_collector.py → data_pack.md
  calculate_factor_inputs.py → factor_inputs.md

Step 2: LLM Valuation Analysis (8 min)
  Classification → WACC → Methods → Cross-validation → Adjustments → Report
  → output/{TICKER}/{TICKER}_valuation_report.md
```

## Valuation Methods

### 1. DCF (Discounted Cash Flow)

- Normalizes FCF by separating growth capex from maintenance capex
- Two-stage model: 5-year explicit forecast + terminal value
- Terminal growth rate: 2.5% (US nominal GDP proxy)
- 5x5 sensitivity table varying WACC and terminal growth

### 2. DDM (Dividend Discount Model)

- Executed only for dividend-paying stocks (yield > 1%)
- Gordon Growth Model for stable dividend growers
- Two-stage DDM for high near-term dividend growth
- Growth rate capped at earnings growth (sustainable payout check)

### 3. Comparable Multiples

- P/E vs 5-year historical range and sector
- EV/EBITDA vs sector typical range
- P/B vs historical
- FCF Yield and Earnings Yield vs risk-free rate

### 4. Graham Number

- For value and hybrid classifications
- Graham Number = sqrt(22.5 x EPS x BVPS)
- Margin of safety calculation

## Company Classification

| Type | Criteria | Primary Methods |
|------|----------|----------------|
| Growth | Revenue CAGR > 15%, P/E > 25x | DCF, Revenue multiples |
| Value / Mature | Stable earnings, dividend yield > 2% | DDM, Earnings multiples, Graham |
| Hybrid | Mix of characteristics | All methods |
| Distressed | Negative earnings, high leverage | Asset-based |

## Qualitative Adjustments

When `qualitative_report.md` is available, the valuation incorporates:

| Dimension | Adjustment |
|-----------|------------|
| D1 Revenue quality | Reduce DCF growth rate if profit quality is LOW |
| D2 Moat | Adjust terminal growth ±0.5% based on moat rating |
| D3 Cyclicality | Reweight scenario probabilities (bear/base/bull) |
| D4 Management | Apply governance discount (5-20%) if management is poor |
| Cross-validation | Additional uncertainty discount if material contradictions |

## Output

The report includes:
- Summary table (valuation range, central estimate, upside/downside)
- WACC derivation
- Each method's full calculation with sensitivity tables
- Cross-validation matrix comparing all methods
- Qualitative adjustments (if applicable)
- Key assumptions and risks

## Integration with Other Modules

```
/business-analysis AAPL  →  qualitative_report.md  ─┐
                                                      ├→  /valuation AAPL  →  valuation_report.md
yfinance_collector.py    →  data_pack.md            ─┘

/us-qy AAPL  (uses different valuation approach: GG-based Factor 4)
```

The `/valuation` module provides traditional intrinsic value estimates, while `/us-qy` uses the
GG penetration return rate framework. They are complementary — `/valuation` answers "what is it
worth?" while `/us-qy` answers "what return can I expect as an owner?".

## Currency Handling

For foreign filers (e.g., NVO filing in DKK), the module:
1. Detects reporting currency from §1 Company Profile
2. Applies FX conversion to all financial data before valuation
3. Presents all results in USD

This addresses the DKK/USD mismatch issue discovered in the NVO analysis.
